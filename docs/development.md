# PocketDesk 开发说明

给开发者看的：设计决定、各阶段的做法和测试结果、踩过的坑、构建方法。使用说明见 [README](../README.md)。

在局域网内，用手机浏览器查看并触控操作 Windows 电脑。不用装 App。

这是 [hujiaxing09/pocketdesk](https://github.com/hujiaxing09/pocketdesk) 的重写版。旧版基于 Sunshine + MoonlightWeb，能用但太重。新版的目标是：每台电脑一个小程序，手机直接连接，不需要网关和电脑之间的 PIN 配对。旧版在新版达到同等可用之前继续保留。

> 当前状态：阶段 0、1、2、3 已验收通过。0.4.5 安装包装在 zero（NVIDIA）、.53、.233 和一台只有 Intel 核显的电脑上，iPhone 和安卓手机都能用；锁屏、UAC、远程桌面都验证过。

## 需求

- 手机（iPhone Safari，或安卓 Chrome/Edge）和被控电脑在同一个局域网。
- 看到电脑桌面，用触控完成点击、双击、拖动、右键、滚轮，能打字（包括中文）。
- 可以控制多台电脑，在页面上切换。
- 画面要接近 Sunshine 的流畅度，所以**从一开始就用硬件 H.264**，不用截屏加 JPEG 的方案。
- 安装包可以安装和卸载，卸载时可以删除使用记录，可以查看日志。

## 为什么不用 Sunshine + MoonlightWeb

Sunshine 是游戏串流服务器，MoonlightWeb 在电脑上跑一个 Moonlight 客户端再转成 WebRTC。对这个需求来说，代价包括：网关和每台主机之间的 PIN 配对、手机的二次授权、用字符串匹配给上游 JS 打补丁、约 90 MB 的安装包，以及入口电脑成为单点。旧仓库里大量代码都在处理配对和证书问题。

## 技术方案

```
每台被控电脑：PocketDesk 程序
  DXGI Desktop Duplication 截屏（画面留在显卡里）
  → FFmpeg 调硬件 H.264 编码（NVENC / QuickSync / AMF，低延迟：无 B 帧、按需关键帧；做法照 Sunshine）
  → WebRTC 视频轨（libdatachannel：RTP 打包，响应手机的重传请求 NACK 和关键帧请求 PLI）
手机浏览器（Safari，页面必须是 HTTPS）
  → RTCPeerConnection 接收，<video> 硬件解码显示
  触控 → WebRTC DataChannel JSON → 电脑上注入合成触摸（照 Sunshine），触控板模式和键盘用 SendInput（中文用 KEYEVENTF_UNICODE）
  信令：页面通过 HTTPS 请求和电脑交换 SDP
```

原则：尽量向 Sunshine 靠拢。Sunshine 是 GPL-3.0，本项目也是，截屏、编码参数、输入注入的代码可以直接搬。注意 Sunshine 本身不用 WebRTC（它用 Moonlight 私有协议：RTSP 建会话，UDP 上的 RTP 加 FEC 传视频，ENet 传控制和输入）；浏览器不能直接收发 UDP，WebRTC（也是 UDP 上的 RTP）是浏览器里离它最近的做法。

## 已决定的事（第一次开发会话，2026-11-20）

1. **开发语言：C++（MSVC）**。直接调用 D3D11 和 DXGI，与 Sunshine 一致，程序体积小。代价是 HTTPS、WebRTC、证书生成、托盘这些要靠引入库或者自己写。
2. **HTTPS 证书：每台电脑各自生成根证书**。根证书带名称约束，只能签局域网 IP 和 `.local` 名称；电脑用它签自己的服务器证书，IP 变了就自动重签。手机给每台电脑装一次描述文件，再到"证书信任设置"里打开。各台电脑不共用根证书，因为共用就要在电脑之间传私钥，等于又加回了配对。iOS 对服务器证书的要求：有效期不超过 825 天、必须有 SAN、EKU 包含 serverAuth。
3. **手机授权：每台电脑各自扫码或输入 6 位数字**。授权一次多台共享需要电脑之间配对，不要；多台电脑的令牌由手机自己保存（阶段 2 的钥匙串）。授权永久有效，直到在电脑上移除。
4. **许可证：GPL-3.0**。和旧仓库一致，可以直接使用 Sunshine（GPL-3.0）的代码。
5. **HTTPS 服务：cpp-httplib + OpenSSL**。视频和输入都走 WebRTC，HTTPS 只需提供页面和交换 SDP，单头文件的 cpp-httplib 就够用，不需要 WebSocket，也不用编译 Boost。OpenSSL 同时负责生成带名称约束的根证书和服务器证书。没有选 Windows 自带的 http.sys + Schannel，因为它绑定证书和 URL 需要管理员权限。
6. **构建：CMake + vcpkg 清单模式**。依赖写在 `vcpkg.json` 里，triplet 用 `x64-windows-static`（静态链接，安装后不依赖 VC++ 运行库）。用 VS 2026 自带的 CMake 和 vcpkg 即可，不需要另外安装。
7. **视频传输：WebRTC（服务端用 libdatachannel）**。视频走 WebRTC 视频轨，触控和键盘走同一连接里的 DataChannel。理由：
   - 走 UDP，丢一个包只影响那一帧，不会像 TCP 那样让后面的帧都等重传；自带重传请求（NACK）、关键帧请求（PLI）和拥塞反馈。Moonlight 也是走 UDP。
   - 旧版 MoonlightWeb 到手机这一段就是 WebRTC，已经在这台 iPhone 上证明流畅度可以接受。
   - 解码交给 Safari 自己的 WebRTC 管线，不依赖 WebCodecs。
   - 代价：连接建立（ICE/DTLS/SRTP）复杂、难调试；播放缓冲由 Safari 决定，延迟没法自己压；Safari 上同样要 HTTPS（非安全页面不做 ICE），证书方案不变。
   - 比较过的另外两种：WebSocket + WebCodecs（最简单、延迟全由自己控制，但 Wi-Fi 丢包重传时会整体卡顿）；WebTransport（iOS 26.4 才支持，C++ 服务端没有成熟的库）。
   - 阶段 0 要测端到端延迟。如果 Safari 的播放缓冲让延迟太高，停下来商量；备选是用 DataChannel 传 H.264、页面里用 WebCodecs 自己解码。
8. **硬件编码：FFmpeg（与 Sunshine 一致）**。用 FFmpeg 的 h264_nvenc / h264_qsv / h264_amf，截屏得到的 D3D11 纹理在显卡上转成 NV12 交给编码器（Intel 要先换成 QSV 帧，见“已知的坑”），各家显卡的低延迟参数照搬 Sunshine。没有选 Media Foundation，因为各家显卡的 MF 编码器可调的低延迟选项少且不一致，Sunshine 的代码和参数也用不上。FFmpeg 只编译 avcodec 和这三个硬件编码器，不带 GPL 和 nonfree 组件。

## 分阶段计划

每个阶段都有验收标准。上一阶段由用户用 iPhone 在真实电脑上验收通过后，再进入下一阶段。

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| 0 打通画面 | 截屏 → 硬件 H.264 → WebRTC → iPhone Safari 显示，先不做输入 | 在 .53 上用 iPhone 看到桌面，测出延迟、帧率、CPU/GPU 占用 |
| 1 单机可用 | 触控输入（合成触摸）和触控板模式、中文输入、光标、断线重连、高 DPI 和多显示器坐标、码率自适应、扫码授权、托盘程序、日志 | 在一台电脑上能完整替代旧版 |
| 2 多台电脑 | 局域网发现、主机切换、授权方案 | .53 和 .233 都能从同一个页面操作 |
| 3 安装包 | 安装、卸载（可删除记录）、防火墙规则、开机启动；锁屏和 UAC 弹窗下也能操作（系统服务 + 会话内进程，原阶段 4 并入） | 安装和卸载都在干净的电脑上验证，锁屏时能看到并解锁 |

## 阶段 0 结果（2026-11-20）

测试环境：被控电脑是 RTX 3050 笔记本，主屏 2560×1440@165Hz，NVENC 编码；手机是 iPhone，iOS 18.7 Safari，同一个 Wi-Fi。测试时主屏上放一个持续变化的动画窗口。

| 项目 | 结果 |
| --- | --- |
| 画面 | 2560×1440，H.264 Constrained Baseline，CBR 12 Mbps |
| 手机解码帧率 | 59–60 fps，丢帧 0 |
| 网络 | 往返 5–7 ms，丢包 0，重传请求 0，关键帧请求 0 |
| 手机缓冲 | 约 4.3 ms（Safari 接受了 playout-delay 扩展，基本不缓冲） |
| 手机解码 | 约 5.4 ms |
| 延迟估算 | 约 25 ms = 电脑（等帧 + 转换 + 编码）约 12 + 网络 3 + 缓冲 4 + 解码 5，不含手机屏幕显示 |
| 电脑编码 | NVENC 约 4.5 ms/帧 |
| 电脑占用 | CPU 1.5%（16 线程总量，约合单核 24%），GPU 视频编码引擎 21%，3D 引擎 6% |
| 断线重连 | 电脑端程序重启后，手机约 1 秒内自动重连 |

说明：画面静止时没有新帧，帧率会降到个位数，Safari 会把这算作“卡顿”（freezeCount），不是故障。延迟是各段相加的估算，没有做拍屏的端到端实测。

## 阶段 1 做法（2026-11-20）

电脑端参考 Sunshine，手机端的操作方式参考 Moonlight，界面重新设计，不沿用旧版。

- **触控模式**（默认）：手指直接注入成 Windows 触摸（`InjectSyntheticPointerInput`，按住不动的触点每 50 ms 重复注入一次），点按、长按右键、拖动、双指缩放和滚动都由 Windows 自己识别。
- **触控板模式**：单指移动光标，轻点单击，双指轻点右键，双指移动滚动（自然方向），长按或“点一下再按住”拖动，三指轻点开关键盘。手势逻辑在 `web/trackpad.js`，有单元测试（`node --test`）。
- **键盘**：隐藏输入框唤起 iPhone 键盘，输入法上屏的文字整段用 `KEYEVENTF_UNICODE` 发出；上方一排特殊键，修饰键点一下锁定。
- **指针**：在显卡上画进画面。
- **显示器、画质**：手机菜单里切显示器、码率（自动 3–20 Mbps 按丢包率调整，NVENC 在线改码率不重开）、分辨率、帧率。
- **授权**：托盘图标打开本机配对页，显示一次性二维码（10 分钟、用一次）；手机扫码后换成长期令牌，电脑只存 SHA-256。配对页可以移除手机。
- **托盘程序和日志**：没有控制台窗口；日志按天写到程序旁边的 `data\logs`，保留 14 天，包含手机每 2 秒回报的统计和每次触摸按下的桌面坐标。
- 按钮布局：有黑边时放在黑边里，没有黑边时贴边浮动，可以拖动。

## 阶段 2 做法（2026-11-20）

多台电脑之间没有任何一台当“入口”，串联放在手机上：

- **手机钥匙串**：手机页面保存每台电脑的编号（根证书 SHA-256 的前 16 位）、名字、地址和授权令牌，存在 localStorage，同时编码进网址的 `?ring=`（主屏幕图标自带全部授权，数据被清时也能恢复）。逻辑在 `web/pcs.js`，有单元测试。
- **页面内直连切换**：不管页面是从哪台电脑打开的，都直接向目标电脑的 HTTPS 接口申请连接（跨域，靠令牌鉴权；只允许局域网私有地址和 `.local` 的来源），视频和输入走 WebRTC 直连。原来那台电脑不参与。
- **离线缓存**：Service Worker 缓存页面本身（`web/sw.js`），提供页面的那台电脑关机时也能打开，再去连别的电脑。
- **局域网发现**：每台电脑每 5 秒在各网段广播一次（UDP 47100）名字、编号、端口和全部局域网地址；页面向任意一台已授权的电脑要列表。电脑之间只是互相看得见，不互相信任、不配对。手机优先用和当前电脑同一网段的地址。电脑换了 IP 时，页面会试所有已知地址并重新问列表。
- **授权**：电脑的配对页同时显示二维码和 6 位数字，一次性、10 分钟有效、输错 5 次就换。手机在页面里点“添加电脑”，输入数字或在页面内扫码。授权永久有效，直到在电脑配对页里移除；移除时会立即断开那部手机正在进行的连接。手机也可以把不用的电脑从列表里删掉。同一部手机再次授权（Safari 和主屏幕 App 各一次、或删掉电脑后重加）时合并成一条记录：手机第一次打开时随机生成一个编号，授权时发给电脑，并随网址（`?p=`）在 Safari 和主屏幕 App 之间传递；没有编号时（例如用相机扫码进 Safari）按“同名且同一个 IP”认。一条记录最多保留最近 4 个令牌，配对页显示最近 IP 和浏览器个数。
- **不占用电脑资源**：手机锁屏或切到别的 App 时立刻断开，电脑马上停止编码，回来自动重连（约 1 秒）；默认 10 分钟不操作自动断开（菜单里可选 5/10/30 分钟或从不），点一下继续；菜单里也可以手动断开。没有手机连着时电脑关闭编码器。
- **手机上的别名**：可以给电脑起一个只在这部手机上显示的名字，电脑本身的名称和 IP 不变，局域网发现也不会覆盖它；别名同样写进 `?ring=`。
- 第一次连一台新电脑，手机仍要在 Safari 里安装并信任它的根证书（每部手机每台电脑一次）；页面会检测并引导。
- 测试时可以在同一台电脑上跑第二个实例：`--data 目录 --https-port 47444 --http-port 47081 --name PC-B`。
- **切换不等旧连接**：每次连接带编号，新连接一开始旧的就作废（上一台电脑关了、还在“查找中”时切到别的电脑，立刻生效）。

## 安卓手机（2026-11-20）

页面一开始按 iPhone 做，底层（WebRTC、H.264 硬件解码、触摸事件、HTTPS）都是通用的，安卓 Chrome 也能用。针对安卓的调整：

- **证书**：设置页按手机类型显示步骤。安卓直接打开时点“高级 → 继续前往”；安装证书是下载 `.crt` 后到“设置 → 安装 CA 证书”里选它。Chrome 和 Edge 认手机里装的证书，Firefox 默认不认，只能直接打开。
- **全屏**：菜单里有“全屏”按钮（iPhone 网页不支持全屏，不显示）；也可以“添加到主屏幕 / 安装应用”，`web/manifest.json` 让它从桌面图标打开时直接全屏。安卓主屏幕 App 和 Chrome 共用存储，不需要靠网址带授权。
- **返回手势**：安卓从屏幕边缘往里划是“返回”，操作电脑时容易误触。页面在历史记录里多放一层：返回时先关菜单或键盘，什么都没开时提示“再返回一次退出”。Chrome 只认用户点过屏幕之后放的历史记录，所以在触摸结束时放。
- **键盘**：Gboard 连英文也按单词组词，按空格或点候选词才上屏，所以英文也是一个词一个词发到电脑。组词时在键盘上方显示还没上屏的内容（中文拼音同样适用）。
- **手机名**：新版 Chrome 的 UA 里型号固定为 “K”，改用 `navigator.userAgentData` 取真实型号。
- **顶部留白**：横屏顶部让出 24 点只对 iPhone，安卓不留。
- 以上只在电脑浏览器里模拟安卓测过，还没在安卓真机上验证（尤其是键盘和证书安装）。

## 阶段 3 做法（2026-11-20）

参考 Sunshine，装成系统服务，锁屏、UAC 弹窗、开机还没登录时也能连：

- **两个进程**：`pocketdesk.exe --service` 是服务，以 SYSTEM 运行，不截屏也不联网，只负责在当前显示在屏幕上的会话里启动 `pocketdesk.exe --agent`（复制服务自己的 SYSTEM 令牌、改成那个会话号，`CreateProcessAsUser` 到 `winsta0\default`）。选会话的规则：有人在电脑前登录着就用控制台会话；否则有人用远程桌面连着就用远程桌面的会话（没接显示器的主机只有这时才有画面，托盘图标也才出现在远程桌面里）；都没有就用控制台会话（登录界面、锁屏）。程序退出、崩溃或会话切换（注销、切换用户、远程桌面连上或断开）时重新启动它；启动后很快就退出的，等待时间逐次加倍，最长 1 分钟。
- **切桌面**：锁屏和 UAC 显示在 Winlogon 桌面上，只有 SYSTEM 能进去。截屏线程在重建桌面复制前、注入输入失败时，把线程切到当前接收输入的桌面（`OpenInputDesktop` + `SetThreadDesktop`，即 Sunshine 的 `syncThreadDesktop`）再试。SYSTEM 权限也顺带解决了“操作不了管理员权限窗口”（UIPI）。
- **以用户身份打开**：程序是 SYSTEM，托盘里“扫码连接”“打开日志文件夹”用 `WTSQueryUserToken` 拿到登录用户的令牌，以用户身份打开浏览器和资源管理器。托盘窗口放行资源管理器发来的托盘消息（`ChangeWindowMessageFilterEx`），否则高权限窗口收不到点击。
- **退出和恢复**：托盘里点退出时，程序以退出码 3 结束，服务随之停止（下次开机自动启动）；从开始菜单打开 PocketDesk 会重新启动服务（安装时给了已登录用户启动服务的权限）并打开配对页。已经在运行时，从开始菜单打开只会打开配对页。
- **IP 变化**：开机时网络可能还没连上。程序每 5 秒检查一次本机 IP，变了就以退出码 4 结束，服务立即重启它，证书和二维码随之更新。
- **安装包**：Inno Setup 7（`installer/pocketdesk.iss`，`installer/build.ps1` 一步构建，输出 `dist/PocketDesk-<版本>-setup.exe`）。向导可以选安装位置，数据在安装位置下的 `data`。安装包只复制文件，其余由 `pocketdesk.exe --install` 做：注册并启动服务（自动启动，服务进程意外退出 5 秒后重启）、添加防火墙规则（按程序放行，所有网络类型）、收紧文件夹权限。升级前先停服务。
- **权限**：程序以 SYSTEM 运行，普通用户如果能改程序文件夹，换掉 exe 就能拿到 SYSTEM 权限。所以安装时把程序文件夹设为只有 SYSTEM 和管理员能改；`data`（根证书私钥、授权记录）只有 SYSTEM 和管理员能读；`data\logs` 普通用户可以看。
- **卸载**：`pocketdesk.exe --uninstall` 停止并删除服务、结束还在运行的 PocketDesk、删除防火墙规则；最后问是否删除 `data`（授权记录、证书和日志），选“是”就不留痕迹，选“否”则重装到同一位置后手机不用重新授权。静默卸载时保留。
- 不装也能用：直接运行 `pocketdesk.exe`（便携方式）和以前一样，只是锁屏时不能用。

## 已知的坑

- 程序以普通权限运行时，Windows 不允许它操作以管理员身份运行的窗口（例如任务管理器）。
- 高 DPI 和多显示器下坐标换算容易点偏。
- iPhone Safari 切到后台会断开连接，必须自动重连（WebRTC 要重新协商）。
- 不同显卡的硬件编码器行为不同（支持的档次、码率控制、关键帧请求），需要在 NVIDIA、Intel、AMD 上各测一次。
- Safari 的 WebRTC 对 H.264 有要求：档次要在 SDP 里协商一致（profile-level-id）、packetization-mode=1、SPS/PPS 随每个关键帧下发。
- NVENC 头文件（ffnvcodec）的版本决定最低 NVIDIA 驱动版本。vcpkg 默认的 13.1 要求 610 以上的驱动，在 API 13.0 的驱动上直接打不开编码器，所以 `vcpkg.json` 里固定为 11.1.5.3（驱动 471.41 以上）。
- NVIDIA 上 FFmpeg 建 NV12 纹理数组并带 RENDER_TARGET 会报 `E_INVALIDARG`，编码纹理池改为每帧单独一张纹理。
- Intel 的 `h264_qsv` 只收 NV12 或 QSV 帧，直接给 D3D11 纹理会报 “Invalid argument”（NVIDIA、AMD 的编码器收 D3D11 纹理）。做法同 Sunshine：从截屏用的 D3D11 设备派生 QSV 设备，在它上面建只有 1 帧的 QSV 帧池（`MFX_MEMTYPE_VIDEO_MEMORY_PROCESSOR_TARGET`，底下的 D3D11 纹理带 RENDER_TARGET），取一次后每帧重复使用，从 `mfxHDLPair` 取出纹理画进去。帧池多于 1 帧时 FFmpeg 会建 NV12 纹理数组，带 RENDER_TARGET 的纹理数组很多驱动不支持（Iris Xe 上 `Could not create the texture (80070057)`）。QSV 的纹理按 16 对齐（1080 变 1088），视频处理器要设输出区域，只画左上角，否则画面被拉伸。不需要独立显卡，Intel 核显（Iris Xe、UHD）就有硬件编码。
- FFmpeg 自己的警告和错误默认打到 stderr，程序没有控制台时看不到，已经转进日志（`FFmpeg: ...`）。编码器打不开时手机会提示原因，不再是无声的黑屏。
- iPhone 横屏全屏时，屏幕最上沿约 20 点被 iOS 留给下拉通知中心，触摸不会交给网页（原生 App 可以让系统手势让路，网页不行）。横屏时画面整体下移 24 点，桌面顶部的标签页和窗口按钮才点得到。
- Safari 遇到不受信任的证书时可以点“访问此网站”临时放行，之后网页和 WebRTC 都能用，看起来和装了证书一样。但这种例外不保证长期有效，跨电脑切换时也不一定生效，两种方式都支持，不强制安装证书：设置页同时给出“直接打开（点访问此网站）”和“安装证书（更稳定）”，已经能连上时也不自动跳走。
- iPhone 从主屏幕打开的网页 App 和 Safari 存储不互通。授权令牌同时放在网址的 `?k=` 里，“添加到主屏幕”会保存完整网址，主屏幕图标就自带授权。
- 截取的画面不含鼠标指针，要自己画（参考 Sunshine：透明部分按 alpha 混合，I 形光标这类反色部分用反色混合）。
- 普通权限的进程不能向管理员权限的窗口注入输入（UIPI），锁屏和 UAC 界面也一样。装成系统服务后解决（阶段 3）。
- 系统服务里的 SYSTEM 进程直接 `ShellExecute` 打开网址，浏览器会以 SYSTEM 身份运行，必须换成登录用户的令牌。
- 没接显示器的主机（例如 .53）没有画面可截，锁屏界面也没有。只接一根 HDMI 线不算，显卡要读到显示器信息（EDID）才会输出，要插 HDMI 显卡欺骗器（假显示器）。远程桌面连着时用的是远程桌面自己的虚拟屏幕，断开后就没了。手机上会提示原因。
- Windows 只在主显示器上显示锁屏，选了扩展屏时锁屏是黑的。
- 用远程桌面连着一台电脑、又把远程桌面窗口最小化时，Windows 会停止绘制那个会话，PocketDesk 截到的是黑屏。电脑在连接时告诉手机自己是不是在远程桌面会话里（`hello` 消息），手机发现画面全黑超过 3 秒就提示原因。想最小化也不黑屏，可以在发起远程桌面的那台电脑上设置 `HKCU\Software\Microsoft\Terminal Server Client` 下的 DWORD `RemoteDesktop_SuppressWhenMinimized = 2`。
- 互斥量由 SYSTEM 创建时，普通用户再创建同名互斥量得到的是“拒绝访问”而不是“已存在”，两种都要当成已在运行。

## 构建和运行

需要 Visual Studio 2026（含 C++ 桌面开发），它自带 CMake 和 vcpkg。在 PowerShell 里：

```powershell
$env:VCPKG_ROOT = "E:\Visual Studio\18\Community\VC\vcpkg"   # 按实际安装位置
cmake --preset default
cmake --build --preset release
.\build\RelWithDebInfo\pocketdesk.exe
```

第一次配置会用 vcpkg 编译依赖，FFmpeg 要 20 分钟左右。程序启动后会打印两类地址：

- `http://<电脑IP>:47080/`：首次设置页，手机在这里下载并信任这台电脑的根证书（每部手机每台电脑一次）。
- `https://<电脑IP>:47443/`：画面。点屏幕显示或隐藏统计（帧率、码率、延迟估算、丢包）。

端口：TCP 47443（HTTPS）、47080（HTTP），UDP 47500–47599（WebRTC）、47100（局域网发现）。第一次运行时 Windows 防火墙会弹窗，要勾选电脑当前所在的网络类型（网络被设成“公用网络”时必须勾选“公用网络”，否则手机连不上）。
**数据位置**：证书、手机授权记录和日志都放在程序旁边的 `data` 文件夹（例如程序在 `D:\App\pocketdesk`，数据就在 `D:\App\pocketdesk\data`），系统里不留别的文件。直接运行时程序文件夹不可写（例如放在 `C:\Program Files` 又没有安装）才放到 `%LOCALAPPDATA%\PocketDesk`。

- 更新：只覆盖 `pocketdesk.exe` 和 `web` 文件夹，保留 `data`。删掉 `data` 会生成新的根证书，手机要重新信任、重新授权。
- 卸载：用安装包装的，在“设置 → 应用”里卸载 PocketDesk，会删除服务和防火墙规则，并询问是否删除 `data`。直接运行的（便携方式），删掉整个程序文件夹即可，唯一留在系统里的是 Windows 防火墙第一次运行时为 `pocketdesk.exe` 建的放行规则，可以在“Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙”里删除。
- 安装包：`powershell -File installer\build.ps1`，需要 Inno Setup 7（默认找 `.local\innosetup\ISCC.exe`，或者用环境变量 `ISCC` 指定）。

常用参数：`--list`（列出显示器）、`--name 显示名`、`--data 数据目录`、`--output N`、`--encoder h264_nvenc|h264_amf|h264_qsv`、`--fps 60`、`--bitrate 12000`（kbps）、`--web DIR`（直接用源码里的 web 目录，改网页不用重新编译）。

本机调试：`http://127.0.0.1:47080/app/` 只允许本机访问，浏览器把 127.0.0.1 当作安全页面，不装证书也能测整条链路。

## 工作方式

- 每阶段先确认要做什么、怎么验收，做完交给用户测。
- 遇到技术限制或方向问题，停下来说明情况并商量，不要自己绕路解决。
- 不提前堆功能。
