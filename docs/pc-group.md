# 电脑组设计

[← 返回 README](../README.md)

目标：**一部手机授权一次，就能用组里所有电脑；一台新电脑加入一次，组里所有手机都能用它。**
3 部手机 × 4 台电脑，现在要 12 次授权 + 12 次信任证书；有了组以后是 3 次授权 + 3 次证书 + 3 次加组。

## 核心思路：每台电脑本来就是一个组

不区分“有组”和“没组”两种状态：**每台电脑启动时都属于一个组，单独一台就是一个人的组**。
组的全部内容只有三样，组里每台电脑都有一份：

| 内容 | 作用 |
| --- | --- |
| 组的根证书（`certs/ca.key`、`ca.crt`） | 每台电脑用它给自己签服务器证书。手机信任一次，组里所有电脑（包括以后加入的）都受信任 |
| 组密钥（随机 32 字节） | 组里电脑之间同步时互相认证 |
| 组记录（成员电脑 + 已授权手机） | 在组里自动同步，任何一台电脑上增删，其他电脑很快跟上 |

这样做的好处：

- **老用户升级无感**：升级后，现有的根证书就是这个组的根证书，`devices.json` 里的手机就是组里的手机。手机不用重新授权，也不用重新信任证书。
- **代码只有一条路径**：单台电脑只是“只有一个成员的组”，不用写两套逻辑。
- **加入组 = 换成别人的组**：新电脑拿到组的证书、密钥和记录，替换掉自己原来的，重启一下就生效。

## 电脑身份

现在电脑编号是根证书指纹的前 8 字节。组里的电脑共用一个根证书，所以编号要单独存：

- 新文件 `data/pc.json`：`{ "id": "..." }`
- 升级时用现在的算法算一次（根证书指纹）写进去，以后不再变。手机记着的编号保持不变。

## 组记录和同步

`data/group.json`（替代现在的 `devices.json`）：

```json
{
  "id": "组编号", "name": "组名（默认是建组电脑的名字）", "secret": "组密钥",
  "members": { "电脑编号": { "name": "...", "https": 47443, "ips": ["..."], "t": 1700000000, "removed": false } },
  "devices": { "手机记录编号": { "name": "...", "phoneId": "...", "tokenHashes": ["..."], "created": 0, "t": 0, "removed": false } }
}
```

**合并规则（整个同步只有这一条）**：每条记录带修改时间 `t`，两边合并时逐条取 `t` 大的；时间相同，`removed` 的优先。删除不是真删，而是标记 `removed`，这样关机的电脑下次开机同步时也会知道“这部手机被移除了”。

不同步的字段：手机的“最近使用时间、最近 IP”只记在本机（每台电脑看到的不一样，同步它们只会制造无意义的改动）。

**什么时候同步**：

1. 局域网发现的广播里加两个字段：组编号、组记录版本（记录内容的哈希）。
2. 收到同组电脑的广播、版本和自己不同 → 向它拉一次组记录（HTTPS），合并，有变化就存盘并马上广播一次。
3. 来回几次后所有在线电脑的版本一致，不再有流量。关机的电脑开机后第一次收到广播就会补上。

**刚授权就切换电脑**：手机在 A 上授权后马上切到 B，B 可能还没同步到。B 遇到不认识的令牌时，先向在线的同组电脑拉一次记录再判断（最多等 2 秒），不会误报“未授权”。

**同步的安全**：

- 拉取记录时，发起方只信任“由组根证书签发”的服务器证书（只有组成员有根证书私钥），确认对方确实是组员之后才发组密钥。
- 被拉取方检查组密钥，并拒绝已被移出组的电脑。
- 伪造的广播最多让电脑白拉一次，拿不到任何东西。

## 加入组

在**新电脑**的配对页上操作（局域网发现放在电脑这边）：

1. 配对页的“电脑组”一栏列出局域网里发现的、不在本组的 PocketDesk 电脑（显示它们的组名和成员数）。
2. 点要加入的那台电脑，输入**那台电脑**配对页上的 6 位数字（就是给手机用的那个，一次性、10 分钟有效、输错 5 次换新）。
3. 新电脑把数字发给对方，对方核对后把组的根证书、组密钥和组记录发回来。
4. 新电脑保存这些内容，用组的根证书给自己重新签服务器证书，然后自动重启服务（几秒钟）。
5. 新电脑把自己加进成员列表并广播，组里其他电脑同步到它。

方向这样选的原因：组的秘密只发给**证明自己看到了组内电脑屏幕上数字**的一方，冒充组员的人拿不到任何东西。

加入时，新电脑**丢弃自己原来的手机授权**，完全使用组的记录。如果把原来的授权并进组，那些只授权过新电脑的手机会突然能控制组里所有电脑，这不是用户预期的。

（安全前提和现在一样：第一次配对时假设局域网里没有人在主动做中间人攻击。）

## 移出和退出

- **移出某台电脑**：在任何一台组员的配对页里点“移出”，把它在成员列表里标记为 `removed`。被移出的电脑同步到这个标记后，自己变回一个人的组（新根证书、新密钥、没有已授权的手机）。
- **自己退出**：效果同上，只是在自己的配对页上点。
- 被移出的电脑如果一直不开机，它记得的组密钥也不能再用：同组电脑会拒绝它的同步请求。

## 手机端

手机的钥匙串从“每台电脑一个令牌”简化成“**一个组、一个令牌**”：

```js
ring = { group: '组编号', token: '令牌', phone: '手机编号', current: '当前电脑',
         pcs: { 编号: { name, addrs, https, alias, lastUsed } } }   // pcs 是从电脑那里拿来的成员缓存
```

- **电脑列表来自电脑**：新接口 `GET /api/group`（带令牌）返回组里所有成员，以及电脑这边通过局域网发现到的在线状态和当前地址。手机只显示本组的电脑，离线的灰掉。
- **去掉手机上的“添加电脑”流程**：手机不再自己发现和逐台授权，`app.js` 里发现列表、选电脑、信任证书、逐台输数字这部分（约 200 行）删掉。加电脑改成在电脑上“加入组”。
- **授权**：没有令牌、或者令牌被拒绝时显示授权页：扫组里任意一台电脑的二维码，或者输入它的 6 位数字。
- **一次只属于一个组**：在另一个组的电脑上授权时，提示“切换到这个组”并替换钥匙串。家里和公司两个组的情况先不支持，需要时再加。
- **老钥匙串自动迁移**：升级后手机拿着旧的各台电脑令牌挨个问 `/api/group`，第一个被接受的令牌就成为组令牌。
- 网址里的钥匙串（给 iPhone 主屏幕 App 用的）也随之变短，只有组编号和一个令牌。

## 电脑端配对页

`pair.html` 分三块：

1. **手机连接**：二维码和 6 位数字（不变）。
2. **已授权的手机**：整个组的手机，移除后组里所有电脑都断开它。
3. **电脑组**：组名、成员（在线/离线、移出），局域网里发现的其他电脑（加入它的组），退出组。

## 接口

| 接口 | 谁调用 | 鉴权 |
| --- | --- | --- |
| `GET /api/group` | 手机 | 手机令牌 |
| `GET /api/group/state` | 组内电脑同步 | 组密钥 + 发起方验证组证书 |
| `POST /api/group/join` | 要加入的电脑 | 6 位数字（一次性） |
| `GET /api/local/group`、`POST /api/local/group/join`、`/remove`、`/leave` | 本机配对页 | 只允许本机 |
| `GET /api/peers` | 删除（手机不再需要） | |

## 代码改动

| 文件 | 改动 |
| --- | --- |
| `src/group.h/.cpp`（新，替代 `devices.*`） | 配对码、手机授权、组记录读写、合并、版本哈希、加入/移出/退出；同步客户端（发现版本不同就拉取） |
| `src/certs.cpp` | 根证书可以从组里换掉；电脑编号从 `pc.json` 读 |
| `src/discovery.cpp` | 广播里加组编号和版本；收到同组且版本不同的广播时通知组模块 |
| `src/web_server.cpp` | 上面的新接口；去掉 `/api/peers` |
| `src/main.cpp` | 组装；加入/退出组后用现有的“重启”退出码让服务马上重启 |
| `web/pcs.js`、`web/app.js` | 单令牌钥匙串、从 `/api/group` 拿电脑列表、删掉逐台添加流程 |
| `web/pair.html` | 电脑组一栏 |

预计 C++ 增加约 400 行，网页端净减少约 150 行。

## 实现顺序

1. 电脑身份和组记录：`pc.json`、`group.json`、从旧版迁移。只有一台电脑时行为和现在完全一样。
2. 加入/移出/退出组和配对页（这时组里电脑已经共用证书和授权，但还不会自动同步，加入时的那份就是全部）。
3. 同步：广播带版本、拉取合并、未知令牌先同步再判断。
4. 手机端：单令牌钥匙串、电脑列表、老钥匙串迁移。
5. 在 zero、.53、.233、u1 上测试：加组、手机只授权一次切换全部、移除手机、移出电脑、关机的电脑开机后补同步、从 1.0.0 升级。

版本号定为 1.1.0。

## 测试结果（开发机上两个测试实例，走局域网地址）

- 手机在 A 上授权后立刻连 B：B 先同步再判断，直接通过。
- 手机在 B 上授权，3 秒内 A 也认；在 B 上移除，A 上随即 401。
- B 关机期间在 A 上移除手机、授权新手机，B 开机后几秒内补齐。
- A 把 B 移出组：B 变回单独的组并自动重启，原来的手机令牌在 B 上失效。
- B 重新加入后自己退出：A 的成员列表随之只剩自己。
- 错误的配对码加入组被拒绝；错误的组密钥同步被拒绝（403）。
- 1.0.0 的数据目录：电脑编号与旧算法一致，`devices.json` 里的手机授权搬进组记录。
